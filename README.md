# PyDrill 题库审查管理台 (Admin 纯静态版)

纯前端静态题库管理与审查后台，专用于 `question-bank-v2/` 题库管理、多维筛选检索、标签看板、原地编辑、实时审查与导入导出。

---

## 纯静态特性与架构说明

- **零服务端依赖**：无需 `python3 server.py`，无需 Node.js / npm 构建，纯 HTML + CSS + JS 驱动。
- **免安装随处运行**：
  - 本地浏览器直接双击打开 `index.html`（若因浏览器 `file://` CORS 策略限制无法自动读取 `./data/`，界面会自动提示点击「从本地文件载入整库」选文件即可）。
  - 支持挂载至 GitHub Pages、Cloudflare Pages、Vercel 或局域网静态服务器。
- **移动端友好**：响应式布局，手机、平板与电脑浏览器均可自适应打开并操作。
- **持久化方案**：
  - **浏览器工作副本 (localStorage)**：任何编辑、审核或导入操作均自动 autosave，页面刷新或意外关闭内容不丢。提供「清除本地草稿」随时重置回官方快照。
  - **主持久化 (下载导出)**：提供一键「导出整库」与「导出当前筛选」，下载 JSON 文件到本地后，按需覆盖回仓库 `question-bank-v2/questions.json` 提交 git。
- **代码审查变更说明 (去除 run-check)**：
  - 纯静态浏览器环境出于安全性与无服务端架构，移除了后端的 `python3` 子进程运行沙箱。
  - 原运行区升级为**纯静态审查区**：直接展示代码片段、正确答案与对应选项文本，配备一键「📋 复制代码」按钮，方便在本地终端 `python3` 运行验证。

## 快速使用

### 1. 静态打开方式

#### 方式 A：静态托管 / 局域网服务（推荐）
将 `admin/` 目录（包含 `data/`）直接部署到任意静态托管服务（如 GitHub Pages），或在终端临时拉起轻量静态服务：
```bash
# 进入 admin 目录以静态服务打开（仅用于本地托管，非后端依赖）
python3 -m http.server 8765 --directory question-bank-v2/admin
```
浏览器打开：[http://127.0.0.1:8765](http://127.0.0.1:8765)

#### 方式 B：双击打开
直接在操作系统文件管理器中双击 `question-bank-v2/admin/index.html`：
- 若浏览器允许相对路径读取，将直接自动载入 `./data/questions.json`（65 题）与 `./data/tags.json`。
- 若浏览器阻止 `file://` 请求，页面顶部会出现醒目横幅，点击「📁 从本地文件载入整库」，选取 `question-bank-v2/questions.json` 即可载入。

#### 手机端访问
将本目录托管至 GitHub Pages 或同一局域网下的静态 IP 后，手机浏览器直接打开对应链接即可使用。

## 核心功能与操作说明

### 1. 列表浏览与多维筛选
- **单标签筛选**：点击标签看板上的任一标签卡片即可筛选。
- **组合标签筛选（交集）**：连续点击多个标签或在看板上组合选择，题目必须**同时包含**所选全部标签。
- **状态筛选**：支持快速切换「全部 / 待重审 (`needs_review`) / 草稿 (`draft`) / 已通过 (`verified`)」。
- **关键词全文检索**：支持按题号（如 `q001`）、题干内容、Python 代码片段、选项文本、解析、改动备注进行实时模糊搜索。

### 2. 标签看板（实时内存计算）
- 基于 `tags.json` 权重及当前题库实时统计：
  - `actualCount`：当前标签被题目命中的实际次数。
  - `expectedShare`：按权重算出的理论期望题数。
  - `deficit = expectedShare - actualCount`：
    - `> 0`：橙色徽章标注 **欠频需补充**（出题优先选此标签）。
    - `< 0`：标注 **已超份额**（出题时跳过或暂缓）。
    - `== 0`：标注 **均衡**。

### 3. 原地编辑与版本规则 (Schema 规范)
点击卡片上的「✏️ 原地编辑」打开编辑模态框：
- 严格限制知识点标签数量为 **1–2 个**，且必须存在于 `tags.json`。
- 四个选项完整（A/B/C/D）且指定唯一正确答案。
- 保存编辑修改自动触发 schema 规约：
  1. `status` 自动变为 `needs_review`（改动后须重新核对选项与答案）。
  2. `revised` 变为 `true`。
  3. `revision` 版本自动递增 `+1`。
  4. `lastEditedAt` 记录当前 ISO 8601 时间戳。
  5. 自动同步保存至 `localStorage`。

### 4. 审核通过 (Approve)
对于 `needs_review` 或 `draft` 状态的题目：
- 点击卡片右下角「✓ 审核通过 → verified」。
- `status` 变更为 `verified`，**不增加 revision**，自动同步至本地草稿。

### 5. 导入与导出

#### 导出 (Export)
- **导出当前筛选**：下载当前筛选结果集合 `filtered[]` 为 `pydrill-filtered-YYYYMMDD.json`（无筛选时等价于整库）。
- **导出整库**：下载内存中完整题目数组为 `pydrill-questions-full-YYYYMMDD.json`。
- **将修改持久化回仓库**：
  工作完成后，点击「导出整库」，将下载得到的 JSON 重命名覆盖至 `question-bank-v2/questions.json`，然后 `git commit`。

#### 导入 (Import)
点击顶部「📥 导入数据」，选取本地 JSON 题目文件，支持两种模式：
1. **合并进整库（按 ID 覆盖/追加，推荐默认）**：
   导入文件中的每一题，若 ID 在题库中已存在则覆盖更新；若不存在则追加进题库末尾。
2. **导入到当前筛选结果**：
   仅更新「当前筛选结果集合中已有的题号」；导入文件中不在当前筛选范围的题号将被忽略跳过，且不会追加新题（防止不小心扩大题库）。
- **严格校验**：导入过程逐题校验字段（ID、4个选项、A-D答案、1–2个合法标签），非法题目跳过并生成错误汇总报告，不会导致整体崩溃。
